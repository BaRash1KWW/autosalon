```text

          │

                                         [ Microsoft SQL Server ]
                                         (запущен на хосте Windows)

3. Переменные окружения и секреты 
MSSQL_USER — логин пользователя БД.
MSSQL_PASSWORD — пароль пользователя БД.
MSSQL_DATABASE — имя базы данных.
MSSQL_DOCKER_SERVER — адрес хоста с БД из контейнера (host.docker.internal).
MSSQL_DOCKER_PORT — порт БД (1433).
NODE_ENV — режим работы (production).
PORT — порт приложения (5000).
HOST — хост приложения (0.0.0.0).
4. Команды для запуска и остановки проекта
Запуск (сборка и старт в фоне):
cd deploy
docker compose up --build -d
Остановка:
docker compose down
5. Список ошибок, возникших при выполнении работы, и способов их устранения
Ошибка	Причина	Способ устранения
ConnectionError: Failed to connect to host.docker.internal:1433	SQL Server Express не принимал сетевые подключения из Docker
Включен протокол TCP/IP в SQL Server Configuration Manager, в настройках IPAll указан порт 1433. Добавлено правило в Брандмауэр Windows.
Ошибка входа в SSMS (код 18456)	Отключен смешанный режим аутентификации	В свойствах сервера включен режим "Проверка подлинности SQL Server и Windows"
Login failed for user 'sa'	Пользователь sa был отключен
В SSMS открыты свойства пользователя sa, задан пароль, на вкладке "Состояние" выбрано "Включено". Служба SQL Server перезапущена.
6. Что нужно изменить, чтобы опубликовать проект на реальном сервере?
Доменное имя: Зарегистрировать реальный домен (например, autosalon.ru) и настроить A-запись на публичный IP-адрес сервера.
Сертификаты безопасности: Отказаться от локальных сертификатов mkcert и получить настоящий SSL-сертификат от центра сертификации (например, Let's Encrypt с помощью Certbot).
База данных: Вынести Microsoft SQL Server с локального компьютера на выделенный сервер или использовать облачный сервис (Yandex Cloud, Azure).
Безопасность и секреты: Не хранить файлы .env на сервере в открытом виде. Использовать менеджеры секретов (Docker Secrets, HashiCorp Vault) или переменные окружения CI/CD.
Мониторинг: Настроить сбор логов и систему оповещения об ошибках.
CD (Continuous Deployment): Настроить автоматическое развертывание проекта на сервере после успешного прохождения тестов в GitHub Actions.
